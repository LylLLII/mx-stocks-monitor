# 妙想选股 · 盘中累计观察池

用东方财富「妙想」选股，在交易时段**持续把符合条件的 A 股累计进同一个观察池**，
按代码去重；同一只股票若多次命中，会累计「入选次数」并记录每一次命中的扫描时间点，
方便回看它在盘中的异动节奏。

## 当前筛选条件（A 股）
- 剔除：北交所 / 科创板(688) / 创业板(300) / ST 股 / 退市股
- 剔除风险事件：新规戴帽风险、近三个月减持计划、未来三个月解禁、近三个月监管函或监管工作函
- 量价与技术面：涨跌幅 3%–5%、量比 > 1.5、换手率 5%–10%、总市值 50–200 亿、近 20 日有涨停

> 改条件：编辑 `screener_monitor.py` 顶部的 `QUERY` 一处即可，监控与定时任务都会跟着变。

## 云端自动运行（主力，无需本机开机）
仓库已配置 GitHub Actions（`.github/workflows/monitor.yml`），在**交易时段自动每 5 分钟唤醒一次**；每次运行内部以 **`--loop` 模式每约 2 分钟扫描一次**（默认 3 次/运行），从而把实际筛选密度提到 ~2 分钟：

- 每次云端运行 = 一次 `git pull`（取最新池）→ 循环扫描（2 分钟一次，自动守卫交易时段）→ 统一 `git commit + push` 一次，避免高频 git 冲突。
- 工作流加了 `concurrency` 并发锁，防止两次运行重叠互相 push 打架。
- 盘前盘后自动静默（脚本内置交易时段守卫：9:30–11:30 / 13:00–15:00，跳过周末与午休）。
- `EM_API_KEY` 存在仓库 **Secret** 里，云端自带授权，不依赖你本机。
- 仓库已设为**公开**：循环模式每次运行约 4–5 分钟，公开仓库 Actions 免费额度不限分钟数，全天跑也无压力（私有库会超 2000 分钟/月限额）。
- 想手动触发一次：在仓库 `Actions` 页点 `Run workflow`（可勾选 `force` 忽略交易时段守卫）。
- 密度调参：改工作流里 `python screener_monitor.py --loop` 可加 `--loop-interval 90`（间隔秒）、`--loop-max-seconds 280`（单次运行上限，须 <300）。

所以：**你上班、下班、关机都不影响监控**，观察池由云端以 ~2 分钟密度持续维护。

## 在任意一台电脑部署（可选，用于手动补扫 / 测试）
前置：Python 3.10+。本机运行**不是必须的**——只是备用。

```bash
# 1) 拉取仓库
git clone <仓库地址> mx-stocks-monitor
cd mx-stocks-monitor

# 2) 装依赖
pip install -r requirements.txt

# 3) 首次运行 → 打印/生成授权二维码，手机扫码授权 → 再运行一次即生效
python screener_monitor.py --force

# 之后手动跑（不守交易时段时用 --force；守交易时段直接不带参数）：
python screener_monitor.py --force
```

- `EM_API_KEY` 仅保存在本机 `~/.mx-skills/em_api_key`，**不进仓库**；
  每台机器首次运行需扫码授权一次，之后免授权。
- 脚本已内置 git 自动同步：**运行前先 `pull` 云端最新观察池，运行后再 `commit + push` 合并结果**，
  所以偶尔手动跑一次也不会和云端冲突，两份数据互为补充。

## 观察池文件
`mx_stocks_screener/观察池_累计.csv`

| 字段 | 含义 |
|---|---|
| 代码 / 名称 / 上市板块 | 基本信息 |
| 量比 / 换手率(%) / 总市值 / 涨停次数(近20日) | 入选时的行情快照（妙想选股返回，每次命中会刷新） |
| ST股票 / 退市股 / 戴帽预期(新规) | 风险标记 |
| 首次入选日期 / 首次入选时间 | 第一次被扫到的时刻 |
| 入选价(元) / 入选时涨跌幅(%) | **首次入选时冻结的快照**（信号出现时的价格/涨幅），后续命中不覆盖——这是「策略口径收益」的买入基准。注意：CSV 不再存「实时最新价/涨跌幅」列，只保留这份冻结快照，避免「实时价」与「基准」并存混淆 |
| 最近入选时间 / 入选次数 | 持续命中情况 |
| 入选扫描时间点 | 所有命中时刻，如 `2026-08-04 10:30;2026-08-04 14:30` |

### T+1 跟踪字段（次日表现，自动记录）

对每只股票，在其**首次入选日的下一个交易日（T+1）**收盘后，自动抓取当天开/高/低/收与 **11:30 午间价**，
以「昨收」为基准换算涨跌幅，并给出形态分类。专门解决"上午涨、下午跌"只看收盘会漏掉日内路径的问题。

| 字段 | 含义 |
|---|---|
| 次日_跟踪状态 | 待跟踪 / 已跟踪 / 已补抓（错过窗口后回溯成功） / 已过期（超出回溯窗口） |
| 次日_跟踪日期 | 实际跟踪的 T+1 日期 |
| 次日_开盘涨跌幅 | (开盘 − 昨收) / 昨收 |
| 次日_午间涨跌幅 | 11:30 价格相对昨收 |
| 次日_收盘涨跌幅 | (收盘 − 昨收) / 昨收 |
| 次日_最高涨跌幅 / 次日_最低涨跌幅 | 当日最高/最低相对昨收 |
| 次日_形态 | 如 冲高回落 / 上午涨下午跌 / 高开高走 / 低开高走 等 |
| 策略收益_次日收盘(%) | **以「入选价」为买入基准**的真实盈亏：(次日收盘 − 入选价) / 入选价。回答"跟信号买能赚多少"，而非个股相对昨收的涨幅 |
| 策略收益_次日最高(%) / 策略收益_次日最低(%) | 同理用次日最高/最低价算，代表"次日盘中卖出"的最佳/最差情形（持仓盈亏区间） |

> 数据来源：腾讯自选股公开行情接口（`qt.gtimg.cn` 实时 + `web.ifzq.gtimg.cn` 分时），全部以「元」为单位、无需额外授权；交易日计算用 `chinese_calendar` 排除法定节假日。
> 注：筛选命中仍由东方财富「妙想」MCP 提供，T+1 行情跟踪改用腾讯自选股（更稳定、无单位错位问题）。

**健壮性设计（防静默丢数）：**
- **收盘后独立 cron**：`monitor.yml` 在交易时段每 5 分钟触发外，额外在北京 15:05 / 15:20 跑一次，专门兜底 T+1 抓取，不依赖下午 cron 的尾巴时段。
- **错过窗口可补抓**：若某只股票在 T+1 当天未被抓到（如 CI 延迟），后续运行会用 `day/query` 回溯最近 ~5 个交易日的分时，**完整补回**开/高/低/收与 11:30 午间价，状态标 `已补抓`；仅当超出回溯窗口才标 `已过期`（仍可后续重试）。
- **取数失败告警**：若 T+1 当天应抓却两接口都取数失败，打印 GitHub Actions `::error::` 注解并将运行退出码置 1（CI 运行变红可见），不会静默把股票标成已过期。
- **连通性探针**：`probe.yml` 可手动在 Actions 触发（验证云端 runner 能否连腾讯接口），并每日收盘后跑一次做轻量监控。

## 跨机同步观察池
观察池就是仓库里的 `mx_stocks_screener/观察池_累计.csv`，由 git 维护：

- **主力同步**靠云端 GitHub Actions 自动 `commit + push`，你基本不用管。
- **手动补跑**时脚本会自动 `pull`（运行前）和 `push`（运行后），见上文。
- 单位/家里电脑想看最新清单，随时 `git pull` 即可。

这样云端和两台电脑看到的是同一份累计清单。
